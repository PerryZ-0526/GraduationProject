## 一、结论与路线选择

### 1.1 推荐定位

本项目与 Agent 最合理的结合不是让大语言模型直接控制磨钻，而是构建：

> **基于结构化数字骨面状态、有限动作语法和确定性几何安全门的监督式磨削协作 Agent。**

Agent 负责：

- 理解用户给出的任务级目标；
- 查询当前骨面、计划、质量、误差和延迟；
- 选择已有确定性工具并组织调用顺序；
- 在风险或信息不足时暂停、弃权或请求人工确认；
- 对拒绝原因和状态变化生成可追溯解释。

Agent 不负责：

- 直接生成最终骨面顶点和三角连接；
- 修改几何误差、质量和安全阈值；
- 绕过验证器发布状态；
- 直接输出机械臂关节速度、力矩或磨钻连续控制量；
- 代替外科医生作临床决策。

### 1.2 两类 Agent

| 类型 | 目标 | 项目角色 | 推荐程度 |
| --- | --- | --- | --- |
| 磨削协作 Agent | 任务规划、状态查询、安全监督和人机交互 | 可形成应用层研究问题 | 主线 |
| 科研实验 Agent | 编排批量实验、验证、对照和报告 | 提升研究效率与可复现性 | 支线/基础设施 |

两者应共享工具接口和审计日志，但不能混淆研究结论：科研 Agent 自动跑实验不等于术中 Agent 已经安全有效。

## 二、Agent 在本项目中的定义

### 2.1 Agent 与普通聊天界面的区别

一个可研究的 Agent 至少包含：

1. **观察**：获取当前结构化状态，而不是只阅读自然语言描述；
2. **目标**：接收手术计划、实验任务或用户意图；
3. **规划**：将目标分解为若干可执行步骤；
4. **工具调用**：调用预先定义、参数受约束的函数；
5. **反馈**：读取工具结果和验证器拒绝原因；
6. **记忆**：保存当前任务内的版本、动作和结果，不自行改写历史证据；
7. **停止机制**：完成、失败、弃权、超时或请求人工介入。

如果系统只回答“当前完成度是多少”，它是问答接口；如果它能够基于状态选择 `preview`、`validate`、`pause`、`request_human` 等动作并根据反馈继续规划，才属于本方案中的 Agent。

### 2.2 当前自主性边界

本方案只在仿真或台架前的软件闭环中验证任务级协作。可参考手术机器人自主性分级中的辅助或离散任务层次，但在没有真实机器人、传感器、法规和临床验证时，不应给本系统标注临床自主等级。

建议在论文中使用：

- “监督式任务 Agent”；
- “仿真中的任务级自主规划”；
- “人机协作决策支持”；
- “几何验证约束的 Agent”。

避免使用：

- “自主完成肩关节置换”；
- “临床级智能手术机器人”；
- “无需医生监督”；
- “已保证患者安全”。

## 三、拟解决的研究问题

### 3.1 主研究问题

在连续骨磨削的几何、质量、风险和版本状态均可结构化获得的条件下，Agent 能否：

1. 将自然语言任务稳定转换为有限、可验证的任务动作；
2. 在状态缺失、质量拒绝、版本滞后和未知输入下正确暂停或弃权；
3. 通过工具调用完成预览、验收、状态比较和发布流程；
4. 相较无约束语言模型降低危险动作和错误发布；
5. 相较纯规则系统改善复杂任务的可表达性、恢复能力和人机交互效率。

### 3.2 可证伪假设

**H1：动作约束减少不可执行输出。**  
采用 JSON Schema 或语法约束的 Agent，相较自由文本 Agent，能够降低动作解析失败、非法参数和不存在工具调用。

**H2：确定性安全门阻止错误发布。**  
即使 Agent 提出错误建议，没有绑定当前输入版本、网格哈希和验收阈值的有效验证凭据，也不能发布状态。

**H3：结构化状态优于纯视觉或纯文本状态。**  
输入明确的几何质量、误差、版本和延迟字段后，Agent 对继续、暂停、重算和请求人工介入的判断优于只输入截图或自然语言摘要。

**H4：学习型风险只改善效率，不承担最终安全。**  
接入机器学习风险预测后，Agent 可更早触发预览或人工确认；即使风险模型错误，确定性验证器仍阻止不合格状态发布。

## 四、与现有三项研究的关系

### 4.1 研究一提供可验证几何工具

[研究内容](../../研究内容.md)中的研究一提供：

- 初始骨面和累计扫掠定义；
- 活动区域、来源曲面和真实特征交线；
- 候选局部重建；
- 几何、质量、拓扑、自交和误差审计；
- 接受、拒绝及拒绝原因。

Agent 只能调用这些工具，不重新定义什么是正确骨面。若 Agent 能改变几何算法参数，其参数范围必须预先登记，最终结果仍需经过同一验收。

### 4.2 研究二提供状态机与版本语义

研究二定义一次可发布状态：

`S_k = (M_k, P_k, F_k, t_in(k))`

其中：

- `M_k`：通过验收的骨面；
- `P_k`：与骨面对应的工具位姿或累计轨迹状态；
- `F_k`：完成度、风险、质量和诊断字段；
- `t_in(k)`：该状态对应的输入时间。

Agent 还需读取：

- `state_version`；
- `mesh_sha256`；
- `plan_sha256`；
- `validator_version`；
- `queue_depth`；
- `compute_latency_ms`；
- `display_lag_ms`；
- `accepted/rejected`；
- `rejection_reasons`。

Agent 不得把不同版本的骨面、刀位和风险字段拼成一次回答或发布。

### 4.3 研究三提供风险语义

研究三定义剩余量、完成度、过磨、越界、安全边界和可信范围。Agent 可以：

- 查询这些状态；
- 按规则解释其含义；
- 在达到预设条件时提出暂停或复核；
- 请求切换显示视角或突出风险区域。

Agent 不能自行把几何误差上界解释为统计置信区间，也不能把模型概率解释为临床并发症概率。

## 五、总体架构

```text
用户任务/手术计划/实验目标
                ↓
         意图解析与任务规划
                ↓
      受约束的动作语法/工具选择
                ↓
 ┌──────────────┼────────────────┐
 ↓              ↓                ↓
状态查询      候选预览         计划比较
 ↓              ↓                ↓
 └──────────────┼────────────────┘
                ↓
  确定性几何验证 + 质量门 + 版本门
                ↓
       接受 / 拒绝 / 请求人工
                ↓
     仿真执行、同版本发布与审计
```

### 5.1 分层职责

| 层 | 组件 | 职责 |
| --- | --- | --- |
| 交互层 | 自然语言/图形界面 | 接收目标，展示建议和证据 |
| Agent 层 | 规划器、短期记忆、工具路由 | 分解任务，选择动作 |
| 语法层 | JSON Schema/有限状态机 | 限制动作名称和参数 |
| 工具层 | 重建、比较、预览、验证、暂停 | 执行确定性操作 |
| 安全层 | 几何门、版本门、权限门、人工门 | 决定动作能否生效 |
| 状态层 | 网格、计划、工具、风险和时间 | 保存可追溯事实 |

### 5.2 不依赖特定大模型

正式实验应把 Agent 框架和具体模型分开：

- 同一动作语法；
- 同一工具集合；
- 同一系统提示和任务输入；
- 同一温度或确定性解码设置；
- 可替换本地模型、云端模型或规则规划器；
- 记录模型名称、版本、采样参数和调用时间。

论文贡献应落在状态建模、安全契约、工具约束和验证闭环，而不是只比较某个商业模型的聊天效果。

## 六、状态、动作与工具接口

### 6.1 观察状态

建议提供给 Agent 的结构化观察包括：

```text
task_id
state_version
plan_step
mesh_sha256
plan_sha256
tool_pose
trajectory_coverage
accepted
rejection_reasons
min_angle_deg
min_q
bidirectional_error_upper_mm
completion_ratio
overcut_status
safety_margin_mm
compute_latency_ms
display_lag_ms
queue_depth
model_risk_prediction
model_prediction_interval
```

只有当前任务真正具备的数据才进入状态。不存在或尚未验证的字段必须为 `null/unknown`，不能由语言模型补全。

### 6.2 有限动作语法

建议首版只允许下列动作：

| 动作 | 作用 | 是否改变状态 |
| --- | --- | --- |
| `get_state` | 获取当前结构化状态 | 否 |
| `inspect_plan` | 查询计划步骤和约束 | 否 |
| `preview_segment` | 生成但不发布下一段候选 | 生成临时候选 |
| `evaluate_candidate` | 执行完整几何与质量审计 | 写入审计结果 |
| `compare_with_plan` | 计算剩余量、过磨和边界状态 | 写入状态字段 |
| `request_recompute` | 使用登记配置重新计算 | 生成新候选 |
| `publish_validated` | 发布已绑定验证凭据的状态 | 是 |
| `pause` | 暂停任务和输入消费 | 是 |
| `request_human` | 请求人工选择或确认 | 否 |
| `abort` | 终止当前任务并保留证据 | 是 |

不提供任意 shell、任意 Python、直接文件写入、删除实验结果和修改阈值等工具。

### 6.3 动作示例

```json
{
  "action": "preview_segment",
  "state_version": 134,
  "plan_step": 135,
  "candidate_profile": "registered_default",
  "reason": "进入计划裁剪竖直段，先生成候选并执行完整验收"
}
```

工具端必须检查：

- `state_version` 是否仍为当前版本；
- `plan_step` 是否是允许的下一步；
- `candidate_profile` 是否已登记；
- 当前状态是否允许预览；
- 参数单位和范围是否有效。

自然语言中的 `reason` 只用于审计，不参与安全判定。

### 6.4 验证凭据

`publish_validated` 不应只接受 Agent 声称“已经验证”。验证器应生成不可伪造的结构化凭据，至少绑定：

```text
validation_id
input_state_version
candidate_mesh_sha256
plan_sha256
validator_source_sha256
thresholds_sha256
accepted
time_beijing
```

发布工具重新核对凭据和当前状态。状态版本改变、网格文件改变、阈值改变或验证未通过时，发布必须失败。

## 七、安全契约与人工监督

### 7.1 任务安全契约

每个动作都应声明：

- 前置条件；
- 允许修改的状态；
- 必须保持的不变量；
- 成功后置条件；
- 超时行为；
- 失败和回滚行为；
- 是否需要人工确认。

以发布为例：

**前置条件**

- 候选已完成完整审计；
- `accepted=true`；
- 验证凭据与当前输入版本匹配；
- 工具位姿与网格属于同一状态；
- 不存在尚未处理的更早累计扫掠。

**后置条件**

- 新状态版本严格递增；
- 发布的网格、工具位姿、风险字段和时间一致；
- 审计记录不可覆盖；
- 拒绝候选不会成为可视状态。

### 7.2 强制人工确认

以下情况应请求人工确认，而不是由 Agent 自行继续：

- 首次进入新的轨迹类型或算法适用域；
- 风险模型弃权或分布外；
- 验证器报告未知错误；
- 候选连续多次拒绝；
- 计划、阈值或坐标系发生变化；
- 需要改变已登记算法参数范围；
- 任务涉及真实机器人或传感器执行。

### 7.3 双通道结果

Agent 的每次建议同时输出：

1. **面向用户的简短说明**；
2. **机器可审计记录**：输入版本、动作、参数、工具结果、验证凭据、停止原因。

解释必须引用真实字段。例如，只有验证器给出 `shape_quality` 时，Agent 才能说明因形状质量拒绝，不能凭截图猜测原因。

## 八、实验场景与数据集

### 8.1 场景来源

Agent 基准可从现有项目证据构造：

- 原 138 段计划及其水平、竖直、裁剪分类；
- G1 中 8 个计划参数接受案例；
- 裁剪近切薄壁的质量拒绝；
- 无接触的前置条件拒绝；
- 真实骨面平移 1 mm 后第 7 段拒绝；
- 边界轨迹第 1 段拒绝；
- Geogram 连续布尔超时；
- CPU/CUDA 延迟、积压和回退状态；
- 骨面与刀位版本一致和故意构造的不一致负例。

现有案例用于形成任务模板和回归真值，不足以单独证明自然语言泛化。

### 8.2 场景类别

| 类别 | 示例 | 期望行为 |
| --- | --- | --- |
| 正常推进 | 下一段候选通过全部验收 | 发布或请求人工确认后发布 |
| 前置条件失败 | 无接触、非法计划步 | 拒绝并说明前置条件 |
| 几何质量失败 | 薄壁、小角、低 `q` | 不发布，建议回退或重算 |
| 误差失败 | 双向距离超过预算 | 不发布 |
| 超时与积压 | 后端超时、队列增长 | 暂停、合并合法输入或请求人工 |
| 状态陈旧 | Agent 持有旧版本 | 拒绝动作并刷新状态 |
| 工具错误 | 不存在的动作或非法参数 | 语法层拒绝 |
| 分布外 | 未登记工具、未知轨迹类型 | 弃权并请求人工 |
| 提示攻击 | 用户要求忽略门槛或伪造通过 | 拒绝绕过安全门 |

### 8.3 自然语言任务集

每个结构化场景可生成多种中文表达：

- 明确命令；
- 省略单位；
- 指代上一状态；
- 包含错误步骤号；
- 要求解释拒绝；
- 要求绕过检查；
- 同时包含多个目标；
- 中途改变目标；
- 含模糊空间方向。

自然语言扩增可以由模型辅助生成，但正确动作和安全标签必须由规则与人工审查确定。

### 8.4 数据划分

- 按场景模板划分训练、开发和测试；
- 同一结构化场景的改写不得跨集合；
- 保留未见轨迹类型和提示攻击作为 OOD 测试；
- 记录每条任务的允许动作集合、禁止动作、期望停止状态和所需人工确认。

## 九、对照实验与评价指标

### 9.1 对照系统

| 系统 | 描述 |
| --- | --- |
| 固定规则状态机 | 不使用 LLM，按预定义规则执行 |
| 自由文本 LLM | 无动作语法和安全工具约束 |
| 语法约束 Agent | 有有限动作集合和参数校验 |
| 验证约束 Agent | 增加几何门、版本门和验证凭据 |
| 验证约束 Agent + 风险模型 | 再接入机器学习风险与延迟预测 |

规则系统不是弱基线。对高度结构化任务，规则状态机可能比 Agent 更稳定，应如实比较。

### 9.2 任务能力指标

- 任务完成率；
- 正确动作序列率；
- 首次动作正确率；
- 工具选择准确率；
- 非法工具或参数率；
- 平均工具调用次数；
- 恢复失败后的成功率；
- 人工介入次数；
- 任务总耗时和 Agent 决策延迟。

### 9.3 安全指标

必须区分“提出危险动作”和“危险动作实际生效”：

- 危险动作建议率；
- 安全门拦截率；
- 危险动作实际执行率，目标为 0；
- 未验证状态发布数，目标为 0；
- 跨版本混用发布数，目标为 0；
- 应暂停却继续的漏报率；
- 可安全继续却错误暂停的误报率；
- OOD 弃权率；
- 绕过门槛提示攻击成功率，目标为 0。

### 9.4 解释质量指标

- 拒绝原因与验证器字段一致率；
- 引用状态版本正确率；
- 是否包含不存在的指标或结果；
- 对“不知道/未验证”的正确表达率；
- 人工评审的简洁性和可操作性。

### 9.5 用户研究

条件允许时，可让具备工程或临床背景的参与者完成仿真任务，对比：

- 无 Agent；
- 状态面板；
- 规则提示；
- 验证约束 Agent。

评价任务判断正确率、完成时间、人工操作数、信任校准和 NASA-TLX。小样本用户研究只能作为辅助证据，不能替代客观安全测试。

## 十、相近研究与差异

### 10.1 自然语言与机器人手术交互

1. **Killeen et al., 2024，IJCARS 同行评审论文**  
   *Take a shot! Natural language control of intelligent robotic X-ray systems in surgery*。LLM 将自然语言转换为机器人 C 臂指令，在 212 条医生提示上报告 97% 的满意动作率，并完成体模实时实验。  
   来源：https://pmc.ncbi.nlm.nih.gov/articles/PMC11178437/

2. **Jiang et al., 2025，Bioengineering 同行评审论文**  
   *LL-MAROCO: A Large Language Model-Assisted Robotic System for Oral and Craniomaxillofacial Osteotomy*。使用大语言模型生成颌面截骨计划，并结合视觉匹配转换为机器人可执行指令。  
   来源：https://pmc.ncbi.nlm.nih.gov/articles/PMC12189646/

### 10.2 数字孪生与具身 Agent

1. **Ding et al., 2024，预印本**  
   *Towards Robust Automation of Surgical Systems via Digital Twin-based Scene Representations from Foundation Models*。使用基础模型构建数字孪生场景表示，由 LLM Agent 进行逐步在线规划，并引入监督者反馈。  
   来源：https://arxiv.org/html/2409.13107v1

2. **Seenivasan et al., 2025，预印本**  
   *Beyond Rigid AI: Towards Natural Human-Machine Symbiosis for Interoperative Surgical Assistance*。结合语音、LLM、SAM 和目标跟踪构建可交互的手术感知 Agent。  
   来源：https://arxiv.org/html/2507.23088

3. **Long et al., 2025，Science Robotics 同行评审论文**  
   *Surgical embodied intelligence for generalized task autonomy in laparoscopic robot-assisted surgery*。将视觉解析、策略学习和经典控制器结合，在仿真、离体组织和活体动物场景中验证若干辅助任务。  
   来源：https://doi.org/10.1126/scirobotics.adt3093

### 10.3 手术规划 Agent 与 VLA

1. **Huang et al., 2025，预印本**  
   *Surgical AI Copilot*。构建 Planner–Worker Agent，编排分割、配准、跟踪和视觉问答工具，并建立垂体手术规划数据集。  
   来源：https://arxiv.org/html/2503.09474

2. **Lu et al., 2026，预印本**  
   *ArthroCut: Autonomous Policy Learning for Robotic Bone Resection in Knee Arthroplasty*。将术前 CT/MR、RGB-D、NDI 跟踪、机器人状态和文本意图编码为多模态 token，使用安全约束动作语法；论文页面报告 21 个完整病例数据、23,205 对 RGB-D 和 7 次台架试验，六项切削平均成功率为 86%。  
   来源：https://arxiv.org/html/2603.03957

### 10.4 领域限制

1. **Yip, 2025，Science Robotics 观点文章**  
   指出手术基础模型面临数据难获取、专家标注不足、隐私和机构数据封闭等问题，不能直接依赖通用互联网数据获得可靠手术能力。  
   来源：https://www.science.org/doi/full/10.1126/scirobotics.adt0684

2. **Schmidgall et al., 2025，Science Robotics 综述**  
   系统讨论手术机器人自主性层次、人工监督和评价要求，可作为本方案限定自主范围的依据。  
   来源：https://www.science.org/stoken/author-tokens/ST-2781/full

### 10.5 与本项目的预期差异

本项目具有一组多数通用手术 Agent 工作没有同时具备的结构化条件：

- 累计扫掠定义的明确材料去除目标；
- 曲面来源和真实特征交线；
- 几何、质量、拓扑、自交和误差证书；
- 骨面、工具位姿、风险字段和时间戳的共同版本；
- 拒绝、回滚和不发布语义。

因此可以研究：

> Agent 如何在精确几何验证器和一致状态机约束下进行任务规划，而不是只评价语言回答是否看起来合理。

这属于待验证的研究定位。在完成更系统的文献检索前，不应宣称为首个或唯一方法。

## 十一、科研实验 Agent 支线

### 11.1 目标

科研实验 Agent 用于降低批量几何实验和证据整理的人工成本：

```text
自然语言研究假设
        ↓
生成受 Schema 约束的实验 manifest
        ↓
调用冻结的实验入口
        ↓
运行独立验证器和回归测试
        ↓
聚合接受、拒绝、误差、质量和耗时
        ↓
生成带哈希和来源的草稿报告
```

### 11.2 可用工具

- 查询已有实验及参数；
- 创建不覆盖历史结果的新实验目录；
- 生成候选参数清单；
- 调用登记的 CPU/CUDA/基线入口；
- 调用单元测试和独立验证器；
- 比较 JSON/NPZ 结果；
- 生成表格和报告草稿。

### 11.3 禁止行为

- 删除或覆盖原始结果；
- 自动降低门槛以获得成功；
- 隐藏失败案例；
- 将未执行计划写成实验结果；
- 伪造引用、日志、哈希或样本量；
- 在未经授权的远程资源上运行；
- 根据语言模型判断替代数值验证。

### 11.4 评价

科研 Agent 也需要实验评价：

- manifest 有效率；
- 可复现实验比例；
- 结果数字与原 JSON 一致率；
- 漏报失败案例数量；
- 引用和哈希正确率；
- 人工修改量；
- 相较手工流程的时间成本。

URSA 等科学 Agent 研究已经公开讨论过虚构实验结果和假数据等失败模式，因此“验证器优先、证据不可覆盖”应作为本项目科研 Agent 的硬约束。  
来源：https://arxiv.org/html/2506.22653

## 十二、与机器学习路线的组合

本目录的 Agent 路线可调用[机器学习增强路线](../机器学习增强路线/01-机器学习增强骨面重建与风险预测研究方案.md)，但两者职责必须分离：

| 组件 | 输出 | 是否具有最终决定权 |
| --- | --- | --- |
| 学习型候选排序 | 候选优先级 | 否 |
| 风险/延迟模型 | 概率、区间和弃权 | 否 |
| Agent | 工具调用计划和人工交互 | 否 |
| 几何生成器 | 候选骨面 | 否 |
| 确定性验证器 | 接受/拒绝及证据 | 是 |
| 发布器 | 经凭据校验后的状态 | 仅执行验证结果 |
| 人工监督者 | 高风险任务确认或终止 | 是 |

推荐组合流程：

```text
Agent 查询状态
      ↓
风险模型提示下一段风险或低置信
      ↓
Agent 选择预览、重算、暂停或请求人工
      ↓
候选排序模型推荐尝试顺序
      ↓
确定性生成与验证
      ↓
Agent 解释真实结果
      ↓
人工确认或凭有效凭据发布
```

机器学习模块不可用时，Agent 仍应能够调用固定顺序和规则风险工具完成流程；Agent 不可用时，现有确定性管线仍应正常运行。

## 十三、实施顺序

### 阶段 A-0：只读状态问答

- 统一状态 JSON；
- Agent 只能调用 `get_state`、`inspect_plan` 和 `compare_with_plan`；
- 验证状态引用、版本和解释准确率；
- 不允许改变任何执行状态。

### 阶段 A-1：仿真预览 Agent

- 加入有限动作语法；
- 允许 `preview_segment` 和 `evaluate_candidate`；
- 所有动作仍不发布；
- 构造非法步骤、非法参数、版本陈旧和提示攻击测试。

### 阶段 A-2：验证凭据与受控发布

- 实现与网格、计划、验证器和阈值哈希绑定的凭据；
- 只有 `accepted=true` 的当前版本候选可发布；
- 对规则、自由文本 LLM、语法约束和验证约束四组进行对照。

### 阶段 A-3：风险模型联合

- 接入质量和延迟预测；
- 研究提前预警、弃权和人工介入策略；
- 验证风险模型错误不会导致错误发布；
- 报告效率收益和误报代价。

### 阶段 A-4：交互评价

- 在现有 PyQt/PyVista 原型中加入 Agent 面板；
- 保持状态证据和动作记录可查看；
- 开展客观任务测试；
- 条件允许时补充小规模用户研究。

### 阶段 A-5：硬件前置研究

只有在软件仿真、安全门和人工监督均通过后，才讨论台架或真实机器人接口。进入硬件前需另行定义：

- 控制频率和实时约束；
- 机器人控制器边界；
- 急停和独立安全链；
- 传感器失效；
- 网络和模型超时；
- 法规、伦理和实验审批。

该阶段不属于当前毕业设计的默认必要范围。

## 十四、风险与停止条件

| 风险 | 证据 | 处理 |
| --- | --- | --- |
| Agent 幻觉工具或参数 | 不存在动作、单位或步骤号 | 语法层拒绝并记录 |
| 解释与证据不一致 | 引用不存在的拒绝原因 | 解释判为失败，不允许影响执行 |
| 提示攻击绕过门槛 | 要求“忽略检查直接发布” | 发布器只认可验证凭据 |
| 状态陈旧 | Agent 使用旧 `state_version` | 工具拒绝并强制刷新 |
| Agent 延迟过高 | 决策时间超过交互预算 | 回退规则状态机 |
| LLM 不优于规则 | 完成率或安全性无改善 | 将 Agent 降为交互界面或负结果 |
| 模型供应商变化 | API/版本不可复现 | 固定版本、保存请求配置并比较本地模型 |
| 自主范围膨胀 | 开始直接输出连续控制量 | 停止并另立控制与安全研究 |
| 用户过度信任 | 将建议理解为临床结论 | 明示仿真范围，保留人工确认和证据展示 |

## 十五、可凝练的论文表述

### 15.1 推荐方向名称

**面向机器人辅助肩关节磨削的几何验证约束协作 Agent**

### 15.2 方法贡献候选

1. 将动态骨面、工具、计划、质量、风险和时间组织为同版本的结构化 Agent 观察状态；
2. 建立面向磨削任务的有限动作语法和工具接口，使自然语言规划不能直接进入几何发布；
3. 设计与输入版本、网格、计划、验证器及阈值哈希绑定的发布安全契约；
4. 研究规则系统、自由文本 LLM、语法约束 Agent 和几何验证约束 Agent 在正常、退化、陈旧状态与提示攻击场景下的差异；
5. 可选接入学习型质量和延迟风险预测，但保持最终安全独立于模型置信度。

### 15.3 预期成果

- 一套可复现的磨削 Agent 仿真基准；
- 一个调用现有几何管线的监督式 Agent 原型；
- 一组动作、安全、版本和解释指标；
- 正常与负例任务轨迹；
- Agent 建议、工具结果、验证凭据和发布状态的完整审计记录。

### 15.4 不能预先宣称的内容

- 不能把仿真任务完成率称为临床手术成功率；
- 不能把 LLM 的语言解释称为安全证明；
- 不能只测试正常指令而忽略提示攻击、状态陈旧和 OOD；
- 不能用安全门拦截成功掩盖 Agent 本身较高的危险建议率；
- 不能把接入大模型或工具调用本身称为算法创新；
- 不能在没有机器人、传感器和审批时宣称已实现自主磨削。
