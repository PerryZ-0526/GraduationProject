## 2. 基座结构与实际改变

源码目录：`初步实验/连续磨削实验基座`。

| 文件 | 职责 |
| --- | --- |
| `event_store.py` | 不可变事件详细记录、追加索引、检查点、提交和恢复核查 |
| `prefix_reference.py` | 独立参照游标及工具前缀身份；每个新切削事件执行一个原工具 |
| `legacy_adapter.py` | 冻结Geogram材料更新、输入处理、PaMO/活动面候选及输出审计适配 |
| `run_feedback_base.py` | 输入冻结、路线调度、分支父链、阶段落盘、连接恢复与终态统计 |

参照从原初态开始，随后只读取上一条已保存、已核查的独立参照及本次原工具。参照仍采用旧批次实际生成的`preserved_reference.py`中的清理、物理修复及全量嵌入核查；不借用任何质量分支的网格。工具摘要逐事件进入前缀身份链，包含复用保留游标而不重新优化网格。

原版及候选各持有自己的已发布父网格、版本和阻断状态。Geogram来源布尔、来源判定、局部/扩域尝试、候选外部区域契约及原版独立审计沿用冻结实现。距离最大值、P95、RMS和未切削区变化只记录，不依据0.1毫米或其他维护距离阈值拒绝反馈。

参照几何布尔调用次数由历史重放的平方增长改为每事件至多一次。每事件只写本次详细审计和小检查点，不重写全部历史审计。网格复杂度、碰撞、包含查询和完整几何评价仍可能随序列增长，不能据此宣称整个实验每步恒定耗时或整个算法线性复杂度。

独立参照内部原有的`1e-7 mm`清理扰动核对保持历史方法身份；它核查修复是否改变参照对象，区别于已取消的0.1毫米维护偏差停止规则。参照采用与质量输入相同的修复机制，不称完全算法独立的真值。

## 3. 提交、恢复和方法冻结

每个事件按“参照保存→原版保存→候选保存→整步提交”执行。阶段结果写入当前事件文件；详细事件文件先完整写入并同步，再追加带前项摘要的索引，最后更新检查点。

恢复时检查：完整输入清单及全部网格摘要、冻结方法和共同审计源码、基座源码、原布尔/检查器/作者扩展身份、事件顺序、记录摘要、父网格摘要和参照工具前缀。检查点过期时可从最后一条完整索引重建。已完成的阶段可从当前事件文件恢复；已提交事件不重新执行。

只允许一个本机写入者。异常退出后先确认原本机进程终止，并检查本批旧远端命令；发现仍活动的本批任务会拒绝重复执行，不操作其他任务。索引没有换行的未提交尾部单独封存，完整但摘要错误的行不自动修正。孤立详细文件和旧连接目录保留。

尚未写成可恢复阶段结果的工作不能算发布。如果本机中断时GPU工作已完成、结果尚未提交，需要先核实本批远端进程及产物；本版不承诺任意指令位置的精确一次执行。原始工作目录保留，终止后的未提交阶段可能重试，不能把这种重试计成两次有效磨削。

`interrupted`表示环境或执行中断，不把未执行后缀填成算法失败。`paused_at_requested_checkpoint`是显式短批次提交上限，恢复不缩减原768事件分母。所有时间为北京时间。

## 4. 质量处理器接入契约

默认`LegacyQuality`负责既有原版与候选。新处理器文件可通过`--quality-plugin`冻结接入，导出：

```python
def create_processor(engine):
    # 返回实现以下三个方法的质量处理器。
    return Processor(engine)
```

| 接口 | 输入与返回 |
| --- | --- |
| `methods(branch, labels_valid)` | 返回本分支要尝试的方法名称序列 |
| `run(source, labels, tool, method, folder)` | 保存`candidate.obj`及实际执行记录，返回含执行结果与状态的字典 |
| `audit(source, labels, tool, folder, attempt)` | 完成该方法有效性核查，接受状态为`accepted_sampled`，保留实际审计证据 |

新处理器必须提供其拓扑、嵌入、数值有效性及约束证据，不能将失败对象直接标为接受。累计偏差由基座统一统计，不由插件设置距离停止门槛。每个分支仅反馈实际接受的输出，失败、复用、未执行和环境中断分开保存。

当前适配器的环境初始化仍依赖既有PaMO/GPU与编译设施，这是原版配对所需的后端。仅替换三个质量方法不意味着已经交付无PaMO依赖、CPU专用或临床实时的后端。事件账本和参照游标模块独立于PaMO；后续新质量算法可复用当前实验契约及评价资产，再接入它自己的执行实现。新质量算法本身本次未实现。
