## 一、公共实验管线与指标体系

### 1.1 管线总图（在 13 号脚本骨架上扩展）

```
【数据模块】CT/合成模型 ──► 骨面网格 + 计划面(基板贴附面) + 磨削轨迹
      │                        （E1 产出，E2–E7 复用）
      ▼
【更新模块】逐段扫掠体 ──► [可选：受影响区域筛选] ──► 布尔减法 ──► [可选：质量维护]
      │                        （E5 接入）        （E4 对比内核）  （E6 接入）
      ▼
【统计模块】逐步记录：耗时/面数/体积/偏差/三角形质量 ──► metrics.csv + 曲线图
      ▼
【渲染模块】快照PNG（离屏） / 交互窗口（E7）──► 剩余量/过磨着色显示
```

实现约定：延续 13 号 `workflow_demo.py` 的模块划分，把数据/更新/统计/渲染拆成四个可独立替换的模块文件；所有实验共享同一套 CLI 参数（网格规模、行距、序列长度、内核选择），一次代码多组实验。

### 1.2 指标定义（开工前固定）

| 指标 | 定义 | 采集时机 |
| --- | --- | --- |
| 完成度 | 已去除体积 / 应去除体积（应去除=初始骨面∩计划圆柱） | 每步 |
| 几何偏差 | 计划区内顶点相对计划面偏差（z 或法向距离）：max / RMS / 直方图 | 快照点+终点 |
| 单步更新耗时 | 布尔运算墙钟时间（筛选/重网格单独计时） | 每步 |
| 端到端延迟 | 工具位姿输入→屏幕更新的时间（E7） | 交互时 |
| 面数增长 | 当前面数 / 初始面数 | 每步 |
| 三角形质量 | 最小内角分布 / 长宽比分布（退化三角形=最小角<10°） | 快照点+终点 |
| 拓扑健康 | 水密性、流形性（布尔后断言） | 每步 |
| 体积误差 | 相对解析真值（简单情形）或离线高精度参照的体积差 | 终点 |

## 三、E1 真实骨面场景构建

**目的**：把 13 号的合成球冠升级为真实解剖几何，回答"真实曲率、非平面计划面下管线是否成立、会出现哪些退化情形"。

**管线设计**：
1. 骨面来源（按优先级）：① TotalSegmentator 官方示例 CT（含肩部结构）→ 分割 → marching cubes；② 公开解剖模型库的肩胛骨模型（如 BodyParts3D，直接取 STL）；③ 兜底：用解析曲面（椭球窝+随机粗糙度）生成"类真实"骨面——三级来源都先跑通，正式数据可替换。
2. 计划面：从 10 号文献的 Perform 基板规格构造——贴附平面 + 中央凸台（boss）+ 可选 7mm 柱，即**非平面计划**；计划去除区半径按基板 25/29mm。
3. 磨削轨迹：覆盖计划区的井字/螺旋路径，球磨半径 2–4mm 可调。
4. 跑 13 号管线（两遍粗精磨），逐步记录指标。

**评价指标**：完成度、几何偏差（这次计划面非平面，用法向距离场而非 z 差）、退化事件计数（布尔失败/非水密/近重合报警）。

**结果解读**：若完成度>90% 且无拓扑失败 → 真实几何路线放行；若出现近重合失败（精磨阶段磨钻贴已磨面）→ 触发 06 号"容差化相交"预案，E4 中对比内核的鲁棒性；若 marching cubes 网格质量太差（薄片/尖刺）→ 数据模块加预处理（重网格+去噪），工作量另计。

## 四、E2 网格规模扩展

**目的**：量化 CPU 路径的规模上限，回答 13 号遗留的"3ms 能否外推"问题，判定 GPU 的必要性。

**管线设计**：同一场景几何，把骨面网格分别重采样到 ~1k / 10k / 100k / 500k / 1M 面（用均匀细分+重网格生成各级），固定轨迹（如 200 段），各跑一遍，记录单步布尔耗时、面数增长、内存。

**评价指标**：单步耗时 vs 规模曲线；面数增长率（每段布尔净增面数）；实时预算（100ms/步）下的最大可行规模。

**结果解读**：这是本阶段**最重要的决策实验**。若 500k 面时 CPU 单步仍 <50ms → CPU 路线可支撑整个课题，GPU 降为加分项（04 号风险预案一）；若 100k 面已超预算 → GPU 路线（RXMesh 移植）提级为主线，E5/E7 围绕 GPU 设计；中间地带 → 混合（CPU 布尔 + GPU 渲染）。注意剔除干扰：规模实验必须与 E5 的筛选实验联动解读（全网格布尔的耗时会被 E5 的局部化大幅改善，见下）。

## 五、E3 长序列稳定性

**目的**：千步级连续磨削下，误差、面数、网格质量是否累积退化——这决定"要不要周期性重网格、多久一次"。

**管线设计**：固定中等规模网格（如 50k 面），生成 2000+ 段的长轨迹（多遍扫掠同一区域=重复磨削+跨区走刀），无质量维护地裸跑；记录每步指标；终点做三角形质量直方图与几何偏差分布。

**评价指标**：面数 vs 步数（线性/超线性？）；最小角分布随步数的退化；重复磨削区的偏差是否漂移；水密保持。

**结果解读**：若面数线性增长且质量缓变 → 质量维护（E6）按固定频率（如每 100 步）执行即可；若超线性爆炸 → 必须做"删旧插新"的平衡策略或更激进的周期重网格，工作一的方案要相应调整；若重复磨削区出现偏差漂移 → 检查布尔内核的累积舍入（E4 加对照）。

## 六、E4 布尔内核对比选型

**目的**：为工作一选定实现内核，并验证各内核在磨削场景（尤其近重合）下的鲁棒性——这是论文对比实验的预演。

**管线设计**：同一场景+轨迹，分别用 ① manifold3d（13 号已用）② OpenMeshCraft（reference/ 已克隆）③ InteractiveAndRobustMeshBooleans（reference/ 已克隆）跑通；构造专门的**退化用例**：重复磨削同一位置（近重合）、磨钻恰好切过薄壁、切线掠过（相切）。

**评价指标**：耗时、水密保持率、退化用例成败、体积一致性（三内核互相对拍，偏差应<1e-3 mm³ 量级）。

**结果解读**：选型原则是"鲁棒>快"（精度由内核保证，性能由 E5 局部化解决）；若某内核在近重合用例失败 → 从主线剔除，仅作对比基线；三内核体积对拍不一致 → 用解析真值仲裁（简单场景），并把该发现写进实验记录（论文素材）。

## 七、E5 受影响区域筛选加速

**目的**：验证"先筛选受影响三角形、再做局部布尔"比"整网格布尔"的加速比——这是把 13 号管线从"整网格重算"升级为"真增量"的关键，也是工作二的核心工程。

**管线设计**：实现两级筛选：① 基线=整网格布尔（13 号现状）；② AABB/KD 树/八叉树（trimesh rtree 或自建 Morton-LBVH）定位磨钻邻域三角形，仅把邻域子网格送去布尔，再回拼。各级在 E2 的规模序列上重跑。

**评价指标**：单步耗时对比曲线（筛选耗时 vs 布尔耗时分解）；加速比 vs 规模；回拼后的拓扑健康。

**结果解读**：若 100k+ 面时筛选路线比整网格快 10×+ → 增量路线确立，且 E2 的 CPU 规模上限被大幅推高（可能让 GPU 变成纯加分项）；若加速比平平（邻域占总网格比例不降）→ 说明筛选实现有缺陷或场景不受益，回退整网格+GPU。此实验与 E2 联动出结论：**"规模上限 = E2 曲线在 E5 加速后的右移"**。

## 八、E6 网格质量维护

**目的**：验证质量维护模块（Schmidt 式四遍重网格+平滑，或先做简化版"拉普拉斯平滑+边折叠抽稀"）能否把磨削刻痕区的三角形质量与表面精度恢复到目标。

**管线设计**：在 E3 的长序列输出上接入质量维护：受影响邻域内做 ①边分裂（消除过长边）②边折叠（消除碎小三角形）③翻边 ④切向平滑，约束=计划面边界锁定；对比"无维护 vs 每 N 步维护"两组。

**评价指标**：三角形质量直方图前后对比；表面偏差是否因维护而增大（维护不得破坏几何精度——关键权衡点）；维护耗时占比。

**结果解读**：若质量恢复且偏差增量 <0.05mm → 质量模块方案定稿，接入主管线（工作一完整形态）；若维护破坏精度 → 收紧约束（只在切平面内平滑/冻结边界带），或接受较粗的质量目标；此实验产出工作一"质量保持"小节的全部数据。

## 九、E7 交互原型与端到端延迟

**目的**：把离屏快照升级为交互显示，测得真实的端到端延迟与帧率——工作二的第一组正式数字。

**管线设计**：PyVista（VTK 后端，无需 GPU 渲染也能交互）搭三窗口界面：三维骨面（剩余/过磨着色）+ 偏差直方图 + 进度指标；更新循环用真实时钟驱动（轨迹回放）；延迟分解打点（布尔耗时/数据搬运/渲染各计一段）。

**评价指标**：交互帧率（fps）、更新延迟（位姿输入→画面更新，ms）及其分解、长跑 30 分钟稳定性。

**结果解读**：若帧率≥30fps 且延迟<200ms → 实时性结论成立（远超临床需求，见 10/13 号），工作二的性能目标达成；若不达 → 按延迟分解定位瓶颈（大概率是渲染端数据搬运 → 用 GPU 端属性更新或降采样显示解决），瓶颈记录进开题报告。
