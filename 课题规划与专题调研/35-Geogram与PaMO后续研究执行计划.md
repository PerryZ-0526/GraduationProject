## 一、起点与本轮目标

截至2026年09月28日，T0/T1的资产、运行器和审计链主体已经具备，仍需补论文适用前提核对和阶段同步计时；T2完成原版六例、五轮30次复现，原版联合验收均失败。T3已定位两处CUDA近边相交漏标，在隔离变体恢复内部符号；随后经过多轮质量探查，s3/s4坏面最终清零。

最后两例来自同一解析轨迹的两档配置。定向操作依赖顶点编号和解析箱体，最终约2.9万面，原PaMO输出约2千/4千面；最小角仅比25°门槛高约0.023°。这些数据支持局部修复可行性，尚不足以支持自动方法、连续稳定性或速度优势。

当前证据入口为[09号符号修复](../初步实验/Geogram与PaMO组合验证/09-近边符号修复与质量消融结果.md)、[10号质量操作探查](../初步实验/Geogram与PaMO组合验证/10-边缘质量受限修复与特征交会残差.md)和[14号双例静态审计](../初步实验/Geogram与PaMO组合验证/14-解析箱体交线约束与双例静态质量验收.md)。

本轮按三个层次交付：

1. **算法层**：一个无需案例编号、仅依赖运行时输入的质量机制，以及它在哪些条件下降低小角三角形比例的证据。
2. **连续层**：相同运动前缀下的C0/C1原组合与变体，逐状态接受、拒绝和漂移记录。
3. **系统层**：冻结算法后的同精度CPU/CUDA算子对照，以及完整计算、发布延迟和状态年龄。

每个层次都允许得到负结果。通过一个层次不会自动证明后续层次通过。

## 二、主假设与统一验收

### 2.1 只保留一个质量主假设

**待验证假设Q**：从当前Geogram输入识别来源面片及其特征约束，将PaMO输出中的小角邻域对应到这些来源几何，在固定外部网格和几何预算下自动选择合法局部操作，可以降低完整网格的小角尾部比例，并在有效连续前缀内保持这一收益。

Q的候选贡献是“来源几何如何约束局部操作的选择和接受”。短边折叠、翻边、最近点查询和已有重网格器属于复用算子。当前结果没有证明Q有效，也没有证明它比现有算法先进；实现前补齐对应原文、现有方法及算子保证范围的核对。

符号修复记为独立因素S。首版固定使用已有`4×FLT_EPSILON`隔离变体，明确它只是两例支持的数值修复候选。Q的主要对照共享同一个S，避免把符号恢复的收益计入质量机制。S若在薄壁、窄缝或真实孔洞中产生错误，停止该版本，另行处理符号问题。

Q不同于34号H2中尚待证实的“局部化带来性能收益”。本轮先评价几何和质量；局部操作是否节省完整耗时，由后续实测决定。

### 2.2 质量指标与独立有效性条件

| 项目 | 预先固定的口径 |
| --- | --- |
| 开发及独立质量主指标 | 全网格及变化区域最小角低于10°、5°、1°的面数与比例，按路线配对并报告面积占比、总面数、分项代价；较低比例表示更少极小角面，不设事后挑选的硬占比阈值 |
| 连续有效性指标 | 每条路线从初态起通过拓扑、退化、几何与状态一致性检查的连续切削前缀长度`L/N`；`N`由输入协议固定，失败后不拼接后续成功帧；有效前缀内逐状态报告质量分布 |
| 辅助质量 | 最小角≥25°且`q≥0.4`的高质量面数与比例、面积占比、最小角/q分布；退化面和非有限值单列且按有效性条件处理 |
| 拓扑 | 预期分量/空腔、水密、边及顶点流形、绕序；未排除的自交报警拒绝发布 |
| 几何 | 相对独立参照双向表面预算0.1 mm；同时报告相对Geogram输入的维护漂移 |
| 几何证据等级 | 抽样通过、参考误差未知、连续界通过分别记录；场残差不充当距离上界 |
| 代价 | 最终面数、操作数、内存、显存、完整墙钟及各阶段耗时；按合格与拒绝状态分别报告 |

各比例以对应评价区域全部三角形为分母，退化和非有限面纳入分母并单列。25.2°/25.1°仅是旧版Q以25°逐面清零时的开发参数，保留其历史记录，不作为新版接受条件；若继续使用，须作为冻结的优化参数接受同资源消融。外部未改面仍计入全网格统计，并单列变化区与过渡带，防止细分面数稀释尾部比例。

正式几何评价保留每方向8192个固定种子面积样本，并增加特征、窄缝和变化区域检查。对接近门槛的结果，优先补自适应距离界：对源面片采样点到目标网格的距离加上该点覆盖面片的半径，可利用距离函数的1-Lipschitz性质形成细分停止条件；双向执行。浮点查询误差、目标参照的离散误差和误差预算须单独处理，未完成这些条件只报告数值估计或抽样结果。精确求交的Geogram也不能给自身充当唯一真值。

## 三、数据和评价协议先冻结

### 3.1 两次冻结及数据分工

**先冻结数据和协议，再开发Q；开发结束后再冻结代码和参数。** 输入冻结允许核对可读性、单位、解析定义和预期拓扑，但不允许通过候选输出筛选“容易成功”的测试例。

| 数据 | 数量和角色 | 使用规则 |
| --- | --- | --- |
| 历史材料 | 旧四例、33号配置及s3/s4历次输出 | 开发/回归；全部视为已见，不能充当独立测试 |
| 新开发集 | 6条路线，每类1条 | 用于自动规则、有限配置和C0/C1联调 |
| 新独立测试集 | 12条路线，每类2条 | 参数冻结后统一运行；开发期间不查看候选结果 |
| 符号与输入否定性检查 | 薄壁、窄缝、真孔洞、多分量、绕序/退化输入 | 前三类覆盖相对SDF体素宽度0.5/1/2档；合法性和预期拓扑先登记，不要求本应不可处理的输入被接受 |
| 真实CT | 既有肩胛骨16段，随后原138段计划 | 已见应用验证材料；单标本结论，不算12条未见测试路线 |

六类路线：浅磨、重复/近重复、计划边缘、变深/竖直、倾斜交叉、停止/恢复与缺失。每条含4–8个预先登记的切削前缀，停钻、晚到和缺失事件另外记录。重复切削可正确复用几何，但仍要检查该事件已被处理，不把未处理输入当成功。

独立测试每类安排一条闭合倾斜板体和一条具有解析参照的闭合曲面体，例如球体。开发集中也应包含这两类几何，避免全部机制只对箱体平面成立。计划圆域边缘与为实验构造的箱体侧边分别登记；至少覆盖工具未触及、接近和穿过人工裁剪侧面的情况。以输入集合拓扑定义决定能否裁剪，不能因期望简单拓扑而删除穿透案例。

现有共同案例读取器只接受初始平面，曲面体的输入定义、生成和独立参照属于工作包1要补齐的实际任务。曲面数据未准备好不能直接填写已冻结或已验证。

### 3.2 冻结清单必须落到文件

沿用34号种子`20260922`，按`开发/测试/类别/路线`派生独立随机流，保存实际数值。生成器、形状尺度、倾角、球半径、切入深度、路径范围、工具离散等级、时间间隔和预期拓扑统一写入协议；取值范围依据已有物理案例及解析有效性确定，并在**首次生成候选输出前**签入清单。本文没有虚构已经冻结的数据。

清单包含：案例ID、所有事件、单位/坐标、来源、初始网格和各前缀工具、文件SHA256、生成代码SHA、参考方法、参考误差状态、预期拒绝条件、计分分母。用运动与形状参数核查几何重复，不能仅凭文件哈希不同认定为新案例。

重生成Geogram输出时使用manifest中的冻结提交独立检出，不能直接使用当前已有变化的子模块HEAD。盘点时区分文件缺失与权限不可读，两者都不能记作算法失败。

若新测试结果用于定位问题，该套测试立即转为已见材料；后续算法版本保留对它的回归，但须另冻未见输入才能报告新的独立效果。输入或参照失效要保留原案例和原因；补充案例另编号，不能静默替换分母。

## 四、自动机制的最小实现范围

### 4.1 数据契约

Q接收：当前完整Geogram网格`G`、同一`G`经过完整PaMO得到的网格`M`、单位/精度及公共质量参数。可接收由输入CSG运算产生并验证过的来源信息；不可读取评价参照、答案标签、案例专用顶点对或人工选择的待修边。

Q返回：候选完整网格、修改区域、来源匹配与拒绝原因、逐档质量统计、每次操作、累计位移、参数与耗时；拓扑、退化、几何或状态检查失败时返回拒绝和诊断材料，生产状态保留上一有效版本。

必须从完整PaMO输出开始自动执行。不能从已经手工修到只剩3/2个坏面的网格起跑，并称为端到端自动机制。历史输出仅用于小规模调试与回归。

### 4.2 首版自动流程

1. **输入核验**：确认坐标恢复、精度转换和预期拓扑，拒绝无法解释的来源或自交输入。
2. **来源约束**：从`G`的相邻面法向、连接关系和局部几何得到面片/锐边/角点候选；仅按二面角提取的边称为来源网格特征，不能自动解释成真实CSG交线。将`M`局部顶点及面片与`G`关联，至少联合距离、法向和邻域连通检查。DMC后的来源对应需要重建和验证，不能假定标签仍在。
3. **优化邻域**：优先由低于10°的小角面及其相邻高质量面触发，先取一环，必要时仅扩大到二环；固定外边界及未修改区域。匹配多义的近接曲面、短特征、端点或分叉按不确定处理，固定或拒绝，不能平滑穿越。
4. **有限候选**：首版复用短边折叠与双面内边翻转。位置候选来自原端点、中点以及有唯一来源对应的投影点；普通面片点、特征线点、角点使用不同约束。存在来源为两面交线的证据时才沿线移动，不能硬编码`x=2`、`y=−2`或平面系数。
5. **事务式接受**：检查链接条件、重复/退化面、局部碰撞、法向和累计几何偏离；质量变化按10°、5°、1°尾部及25°/q辅助指标记录。局部操作的选择规则应在开发数据上冻结，避免通过增面数稀释比例；有限且非退化的小角面本身不构成状态拒绝。最差角可能下降，须如实记录。
6. **有限终止与全局审计**：每个邻域、每条边和每个位置候选只按冻结顺序评估；操作预算预先固定，邻域最多扩展一次。无合法改善则保留原有效网格并记录“无收益”，不将其改记为失败状态；导出、重载后再做完整独立审计。

编号重排和刚体变换应保持几何意义及判定一致；比较几何/拓扑指标而非字节顺序。重复运行、OBJ导出重载、阈值邻近样本须重点核对。来源匹配不唯一时的拒绝属于机制适用域，必须计入结果。

累计位移和偏离统一相对本次完整PaMO输入快照及来源网格`G`计算，不随折叠、翻边或阶段切换重置；合并顶点保留其父顶点/面片关系。每步可暂存候选，但只有完整独立拓扑、退化、几何与状态审查通过才发布。首版允许最差角在尾部比例改善时暂时下降，须同时记录其幅度；若研究最差角单调约束，则须作为额外消融，不能将14号曾用过的操作直接宣称满足它。

### 4.3 当前探查链如何处理

已有等长重网格、切向调整、分叉联合搜索等不自动全部升级为Q。先核对哪些步骤属于必需的公共底座，哪些确有单独收益，留下能解释的最小链。

若固定全局等长重网格是公共底座，资源匹配对照也使用它，并记录其面数、完整耗时及几何改变。10号记录中s3该步骤产生过8个自交报警，故不能将其假定为安全输入；若复现仍有未排除报警，该分支记录失败。若要新增“修复已自交网格”的能力，需另设问题和保证范围，不能混入首版Q。

| 名称 | 内容 | 作用 |
| --- | --- | --- |
| G | 原Geogram输出 | 记录几何和质量起点，不单独充当完整竞争对手 |
| P | 作者完整三阶段、原公开配置 | 继承34号原版组合 |
| P-match | 原组合的有限开发参数匹配 | 排除只与不适合的默认配置竞争 |
| P+S | 仅符号变体 | 与P比较S的作用 |
| P+Q | 原符号加同一自动质量机制 | 检查Q是否依赖S；原符号导致无效拓扑时明确拒绝 |
| P+S+Q | 主候选 | 与P+S及资源匹配对照比较Q的作用 |

先在开发集决定B是否需要、其固定配置是什么；若Q本身没有全局预处理，也要提供尽可能接近面数和成本的已有方法对照。P-match只能使用作者实际支持的配置；修改内部R的诊断分支不能冒充作者原版公开参数。

回顾07—14号已有配置，建立累计调参账本。沿用34号“原组合和变体各最多8组预声明开发配置”的上限，不能以新脚本或新日期重置预算。重复性运行、消融开关和新测试输入分别标记，不伪装成额外调参。若剩余预算不足，按现有证据选择一套固定配置，或正式记录协议修订后重新冻结，不能静默超额。

静态质量改善与性能结论分别评判：约2.9万面候选不得直接与约2千/4千面原版比较并宣称同资源胜出。至少同时报告默认原版、面数/资源尽可能匹配的强对照，以及同一几何拓扑条件下完整代价；面数不能精确匹配时如实展示差别。达到作者论文的统计档位不代表当前适配保证适用于所有输入，仍需核对原文与代码。

## 七、连续C0和C1的执行语义

- **C0**：`G_k=Geo(G_(k−1),S_k)`，质量维护只生成显示候选`M_k`；`M_k`不反馈给Geogram。
- **C1**：`H_k=Geo(M_(k−1),S_k)`，维护并验收得到`M_k`后才能作为下一步父网格。
- **独立参照R**：从原始骨面及截至k的真实已到达运动前缀单独构建，不能从C0/C1维护结果生成。

每条方法/状态链使用自己的实际父网格，保存父状态哈希；不同分支因反馈产生不同输入属于要测量的现象，不能强行共享维护输出。初态也需验收，初态未通过记`L=0`，不能免费换成候选已经修好的网格让基线起跑。

若任务需要共同初态预处理，须在输入冻结时定义，对所有分支提供同一网格并计入准备代价和额外几何误差；另保留原始初态的结果。不能看到某方法失败后才单独更换其初态。

生产发布首次拒绝后保留上一合格网格、状态与时间戳，不消费并丢掉未完成切削，也不把失败网格送入下一步。离线诊断如需继续，另建分支并保留尚未处理的运动前缀，不计入合格前缀。C0内部几何链可单独诊断推进，但不能因此推进显示版本。

重复或被包含运动的去重只看已到达前缀；记录事件到原语的映射和包含依据。停止/恢复、时间缺失、晚到数据沿用共同记录规则，不能跨缺失段静默插值。停钻等非切削事件单独统计，不充当成功几何更新。

记录至少包含输入/参考/执行/审计失败、几何/拓扑/退化/状态拒绝和有效输出的小角质量分布。正常失败不自动重试到成功；为检查随机性做的复跑全部保留，并与首次运行分开统计。

## 八、独立测试与真实CT

### 8.1 运行及统计

冻结后每方法、每路线做3次完整重复以描述PaMO运行波动；出现异常时按34号最多5次同输入诊断复测，不能用其中最好一次替换正式记录。路线是独立统计单位，帧数、同一路线的s3/s4档位和重复运行不增加独立样本量。

主要报告每条路线逐状态10°/5°/1°小角比例及25°/q高质量占比的配对差、`L/N`、完整完成路线比例，以及各拒绝原因和维护漂移。小样本优先列出全部路线结果和效应量；如给置信区间，按路线而非帧重采样，并预先固定方法和种子。结果不支持优势时明确写“不支持”或“证据不足”，不能用更多同输入重复代替独立路线。

静态终态若与C0保存的同一前缀、输入、配置、运行种子和输出哈希完全一致，可复用其独立审计，不能重复计为新实验。方法或配置不一致时不得共用结果。比较表同时给出预声明总路线、输入有效路线和算法接受路线，参照失效也必须可见。

### 8.2 从CT16段到原138段

先统一CT坐标、单位、计划与初始网格，审计原始缺陷。任何预处理对所有分支一致，保存原输入及额外几何误差；不能只给候选提供更好的初态。全局PaMO改变的全网格仍需验收，不能只检查手术ROI并忽略其他已修改面。

先重放既有16段仿真轨迹并逐步比较，再尝试原138段，后者的成功步数单独计算。若需局部裁剪后补盖，必须先定义闭合输入、边界拼接和外部保真契约；当前不得将开放局部面直接送入假定闭合实体的PaMO。

CT数据和轨迹证据分开标注：公开真实CT不意味着真实磨削轨迹，计算去除量不等于实测磨削量。额外标本可以增加外部验证，但在取得并完成同样冻结之前，不作为已拥有的数据或计划的必然结果。

## 九、CUDA性能和状态发布

先补齐`tool_ms`、`geogram_ms`、PaMO各阶段同步计时、I/O、传输、审计、状态计算及完整`wall_ms`。GPU事件计时与CPU墙钟含义分开，不能用两个异步打印值相减推算某阶段时间；远端网络传输单列。冷启动、编译和驻留执行分别统计。

根据剖析选择一个最影响完整代价且能建立CPU参照的算子，例如候选邻域查询或质量批量计算；具体对象由实测决定。PaMO GPU与Geogram CPU执行不同功能，不能相除当作加速比。CPU/CUDA使用相同算子、输入和精度；若并行实现改变拓扑或候选语义，回到算法层作为新变体评价。

固定算法后预热，进行至少30次配对性能测量，报告均值、中位数、P95、最大值、内存/显存、相对同输入基线的加速及不同输入速率下的服务能力；100 ms占比可作为10 Hz情景的附加描述，不用作单一合格判断。样本不足时不强调P99。微基准和完整管线同时给出，不能删除审计后沿用原验收结论。

继续复用`ValidatedSession`和现有状态定义，检查网格、刀位、完成量、剩余量、计划内过深和计划外去除的版本对应。重复轨迹不重复累积去除；非单值区域采用三维集合体积或明确标记不可判断，不能直接套用高度差。

持续输入使用既有1/2/10 Hz作为明确的合成负载，并记录到达、计算、验收和发布时间。合并显示可跳过中间画面，但物理扫掠必须完整累计。报告队列长度、丢弃/合并语义、显示状态年龄及最坏滞后；误差传播中的速度和标定参数若是假设须明确标注。100 ms仅是10 Hz输入下“每帧赶上到达”的参考，不作为本研究通用硬门槛；慢于该参考仍可研究加速与状态发布，但积压和滞后必须如实呈现。

## 十、GPU安排与停止条件

### 10.1 何时通知并使用GPU

本地协议、输入冻结、代码开发和已有结果审计先完成。**首次实际需要GPU的是工作包3：在新开发输入上运行完整PaMO及符号变体。** 每批远端执行前通知用户本批目的、输入数量和停止条件，使用已授权实例；通知不重新请求已授予的使用许可。连接不可用时保留本地可做任务，并报告具体端点/环境阻碍。

远端分四批：开发静态与符号反例；开发C0/C1与冻结测试；CT16/138段；同精度与持续负载。复用环境，按哈希复用有效输出，不反复安装，不自行租新实例或关闭用户实例。先用开发样本测真实单次耗时和峰值显存，再按`路线数×分支数×前缀数×重复次数`给出该批预算，不能把旧约5秒进程耗时套到所有新规模。

### 10.2 明确停止扩大的条件

| 触发条件 | 执行动作 |
| --- | --- |
| 来源匹配多义、目标约束不相容或参考无效 | 拒绝并记录原因；保留样本，不调低门槛使其通过 |
| S在合法薄壁/孔洞中误封或产生错误符号 | 冻结该负例，停止以S为共同前提的扩大实验；质量模块可在独立合法输入上继续开发 |
| 自动Q在有限开发预算内未降低小角尾部，或相对同资源基线/Q-minus无可归因收益 | 结束该版本，报告质量分布、失败位置和成本；不继续逐顶点修补后宣称自动成功 |
| 收益随同资源基线或Q-minus消融消失 | 不支持所声称机制；记录成本和负结果，修订研究问题 |
| 独立测试未改善预先固定的质量主指标，或改善依靠删除难例/稀释面数/放宽拓扑几何条件 | 结束该版本的优势主张；任何新开发使用新的测试冻结 |
| T4发生漏算、无效网格反馈或跨版本发布 | 停止该分支的合格前缀，修复后重跑开发协议，原失败保留 |
| CUDA无完整净收益或在某个输入速率下积压 | 如实交付延迟、吞吐和状态年龄；不取消CUDA验证，也不降低质量或精度换取未声明加速 |

程序的超时、显存上限和磁盘预算在开发试跑后写入执行清单，冻结测试前固定。预算耗尽时返回明确失败/未完成状态，不隐式缩小输入或偷偷换配置。

## 十二、下一次执行的顺序与完成定义

下一次按以下顺序推进，不再从安装环境或重跑全部旧案例开始：

1. 盘点旧配置和缺失资产，补方法保证与计时的明确缺口。
2. 生成并冻结6条开发、12条独立路线及符号否定性输入；同时固定参考、分母和统计方法。
3. 编写一页Q机制说明，实现无需案例编号的来源匹配与有限局部操作，在历史和开发材料上验证。
4. 需要新PaMO输出时通知用户，进入GPU开发对照；若关口满足继续C0/C1。
5. 完成开发序列后冻结代码，运行独立测试；再依关口进入CT和T6。

**研究阶段完成的判断**：原版与匹配基线可复现；候选输入/输出/约束和适用域清楚；未见路线的配对与消融支持或否定主假设；连续拒绝及状态语义可信；真实CT证据边界明确；CUDA同精度与完整时延有实际结果；所有结论可由保存的文件、命令和版本复查。

完成不以“所有目标必然成功”为前提。若某机制被否定，应给出有证据的边界和下一项研究决策，而不是无限追加局部补丁。
