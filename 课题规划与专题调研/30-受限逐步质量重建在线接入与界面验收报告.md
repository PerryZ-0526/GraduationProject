## 1. 问题与判据

旧`real_bone_interactive_app.py`默认执行Manifold布尔差并直接显示；暂停后的优化副本不满足逐状态质量要求。先前给用户的入口说明没有明确区别，导致完整旧轨迹演示被误认为逐步验收实验。

本次可证伪的集成假设：相同初始骨面、局部轨迹和验收条件下，交互执行的已发布顶点应与既有批量实验逐步一致；任何局部拒绝或整骨复核拒绝都不得刷新已发布网格、刀位及发布步号。后台和显示只允许一个在途候选，不积压工具输入。不是通过末帧优化来补救。

保持原算法的条件与数学定义：单值图域内以初始分片线性骨面和累计球形扫掠确定高度；使用`LocalPatch`历史足迹上界判据，保持原逐面角度、质量与误差证书检查，整骨复核继续检查拓扑、自交报警及其分离复核。质量指标沿用`q=4√3 A/(a²+b²+c²)`，阈值为角≥25°、q≥0.4、受限误差证书≤0.1 mm。详细依据及适用条件沿用19/20号；本次不声称推导了新的误差界。

## 2. 实现与使用

`边界过渡带联合重建/dynamic.py`将既有序列验收改为可暂停消费的`iter_sequence`生成器；原`run_sequence`消费同一生成器，保持批量实验接口。没有替换几何更新、阈值或整骨复核。

`真实骨模型演示/validated_online.py`新增受限在线会话及窗口：

- 初态也重新验收，加载过程中不发布未验收初态。
- 单工作线程计算，主Qt线程接收独立整骨快照；拒绝或错误停止发布，保留最后合格显示。
- GUI发布步号与后台步号分离，刀位只与当前显示网格共同推进。
- 播放、暂停、单步、重新开始、相机旋转缩放、点线模式、刀位开关、指标曲线、结果回放和证据导出。
- 青色为重建域及过渡带，骨色为未修改原骨面。颜色标区域，不是全骨“质量合格”标签。
- 窗口关闭时等待当前验收结束，不强杀线程；旧窗口不会自动加载新代码，必须重启。

在项目根目录执行原命令，现在默认进入上述受限在线模式：

```powershell
.\.venv\Scripts\python.exe .\初步实验\真实骨模型演示\real_bone_interactive_app.py
```

先等待初态验收，然后点“播放计算”或“单步计算”。旧布尔演示仅显式加`--legacy-bool`打开，窗口标题标明不保证逐步质量。自定义骨面、旧截图与末态优化参数不能隐式绕过新默认入口；`--self-test`仍为旧布尔自检，不是新入口验收。

本机Intel Core Ultra 5 225H，沿用项目Python 3.13 `.venv`、Qt/PyVista/VTK/PyMeshLab。无新增依赖、Conda或Docker配置，无远端任务；计算为CPU双精度参照，渲染使用本机图形环境，不宣称CUDA已接入在线窗口。

## 3. 验证结果

命令均在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 初步实验/真实骨模型演示/test_validated_online.py
.\.venv\Scripts\python.exe -X utf8 初步实验/边界过渡带联合重建/test_joint.py
.\.venv\Scripts\python.exe -X utf8 初步实验/真实骨模型演示/test_camera_retention.py
```

新增5项通过（47.374秒），既有联合重建6项和相机2项通过。新增检查覆盖：

1. 默认入口进入新在线模式，旧布尔需显式选择。
2. 完整16步逐状态合格，17张含初态的局部顶点快照与既有`local_1.8.npz`逐元素一致。
3. 真实不适用工具条件导致拒绝，保留上一合格网格和步号。
4. 注入整骨复核拒绝，确认候选不发布；此项是控制流测试，不作为真实几何负例。
5. 实际Qt窗口播放16步、忙时防重入、暂停、视角保持、显示模式、导出、重新开始，以及真实负例在窗口中停止发布。

首次窗口测试使用`CameraPosition`对象直接参与NumPy比较导致类型错误，已改为显式数值数组并通过；几何测试本身通过。VTK/NumPy shape弃用警告仍存在，不修改第三方库。

后续分离GUI发布步号后，一次开放交互窗口复测发生较大相机变化，未能据此确定是人工交互还是程序原因。测试增加只在自动化期间禁用viewport真实输入，保留VTK相机设置和实际定时刷新；最终窗口复测1项通过（21.079秒），包含16步、暂停、模式切换、重新开始和真实拒绝。生产窗口不禁用鼠标。最终导出为`20260909_105322_937166`；下表保留此前完整测试的既定计时样本，不挑选较快复测替换。

## 4. 研究边界

这是用户要求的“受限已验证实验接入在线组件”，不是新的算法成果：既有标本、固定局部图域、3 mm球形工具、z=1.8 mm水平交叉轨迹。局部底网连接固定，尚非一般动态重三角化。

原138段的完整裁剪、跨区域及竖直磨削仍未完成；外部未修改原骨面的差面不被本次局部门槛改写。未提供下游求解器可用性或临床安全证明。窗口没有沿用旧完整计划的完成度/过磨数字，以免不同几何任务间混算。

本次没有重跑强基线或宣称相对已有算法优势，因为变更是共享实验状态与显示交接，验证重点为与既有实验等价。RXMesh导出质量审计、CUDA在线管线及完整三维质量生成仍是后续独立研究任务，不能因界面接通而记为完成。
