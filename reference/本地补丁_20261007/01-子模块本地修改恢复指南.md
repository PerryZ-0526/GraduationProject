## 2. 新机器恢复

先在主仓库执行`git submodule update --init --recursive`，核对各子模块HEAD与02号一致。确实需要恢复相应本地差异时，先检查补丁，再应用：

```powershell
git -C reference/hypercut apply --check ../本地补丁_20261007/hypercut.patch
git -C reference/hypercut apply ../本地补丁_20261007/hypercut.patch
```

其他两项按对应路径执行。不要对不同HEAD或已经有修改的目录强制应用；先确认版本和冲突。若新平台不需要Windows文件模式差异，可保留补丁记录，不必自动应用模式改动。
